# DevPad 交互专项研究

日期：2026-10-07。审查对象：0.7.0-dev.3，源码 e7c44d6。本文补充早先针对 0.6.5 的 PRD。

## 判断

下一轮优先调整记录与交付的流程。日常记录需要稳定的编辑位置、明确的保存反馈、可逆的整理操作；复制需要明确内容范围、格式与顺序；Agent 协作需要随时能看见的任务状态。

建议定位：随手记录文字和图片，需要时把选中的材料交给 Agent。主界面直接服务记录、查找和复制，高级导出与连接配置逐步展开。当前已经修复的默认复制附带指令、复制按钮悬停伸缩等问题，不再作为本轮未解决事项。

## 证据与边界

- 静态审查：App.svelte、CopyControl、SelectField、AgentPanel、TemplateSettings、UpdatePanel、ConfirmDialog。
- 浏览器走查：实际编译的前端，使用独立模拟笔记与模拟后端；通过 Edge 无界面运行，不操作真实剪贴板、日常笔记或桌面鼠标。
- 实测记录：[interaction-audit-evidence.json](design/interaction-audit-evidence.json)。[当前小窗批量截图](design/current-batch-compact.png)使用模拟笔记；[候选主窗布局](design/proposed-notebook-wide.png)来自交互草图。两者均不含真实用户笔记。
- 上轮 Windows 原生验收已证实：独立编辑窗口、正式保存后关闭窗口、草稿中断恢复、实际应用内升级。本轮没有重复操作日常原生实例。
- 竞品依据为官方公开帮助与设计规范。以下方案是针对 DevPad 的设计推论，未经真实用户研究验证；不声称得到竞品内部设计文档。
- 可点击草图：[interaction-prototype.html](design/interaction-prototype.html)。它演示候选流程，不连接真实应用，不表示功能已经实现。

## 当前流程的主要摩擦

| 优先级 | 位置 / 证据 | 对用户的影响 | 建议与验收要求 |
| --- | --- | --- | --- |
| P0 | 编辑：自动保存的是私有草稿；点击保存才成为正式笔记，且保存后关闭编辑窗口。App.svelte:209、313–326 | “已经保存”的心理预期与列表里找不到内容相冲突；连续记录频繁开关窗口 | 默认主窗内编辑，写作中内容可以在列表找回；保存反馈区分“已保存本地”和“保存失败”。独立窗口由用户主动打开。自动持久化、正式笔记及 MCP 可见性须单独规定，不因改文案而扩大访问范围 |

| P1 | 批量栏有 10 个按钮；400×320 时栏高 100px、列表高 122px | 阅读空间被操作栏挤占，多种复制方式迫使用户反复比较 | 常驻“已选 N 条 / 复制 / 更多 / 退出”；模板、图片、移动、任务发布等在同一层展开。窄窗批量栏目标不超过 56px，不按按钮数量无限换行 |
| P1 | “选中顺序”不等于点击顺序。先点第 2 条再点第 1 条，预览仍为第 1 条→第 2 条；makeSession 按 visible 重排 | 看见的名称与得到的结果不同，资料次序容易出错 | 默认“列表顺序”；若保留“点击顺序”，必须存储并使用实际选择次序。复制正文、图文、图片与导出使用同一个排序结果 |
| P1 | 筛选发生变化时 selected 自动清空。App.svelte:81 | 多次选择的成果丢失；用户无法知道筛选是否影响操作范围 | 首轮维持“当前视图选择”，在多选期间保留范围提示，并明确更改筛选将重置选择。将来跨筛选选择需显示隐藏的选中数量，并可查看整个清单 |
| P1 | 删除正式笔记是不可撤销操作，逐次确认。App.svelte:214 | 频繁整理被打断；确认框无法替代恢复能力 | 删除进回收站并显示“撤销”；永久清空才确认。撤销要恢复正文、附件、归属与关联，不能仅移除确认框 |
| P1 | Agent 配置与任务列表混在设置面板，任务主要从设置查看。AgentPanel | 发布之后离开工作区寻找领取状态与结果 | 主导航提供“任务”；连接配置放设置。发布后显示“等待 Agent 领取”、明确内容快照与原笔记关系；返回源笔记和完成结果都可直接访问 |
| P1 | MCP 发布是任务入队，现有服务没有自动唤起 Agent 的调度器 | 用户容易把“已发布”理解为“已经开始执行” | 使用“已进入任务队列，等待 Agent 领取”。展示实际领取者、最近活动与结果；没有可靠会话信号时不显示“Agent 在线”。后续主动唤起应明确选择目标客户端 |
| P1 | macOS 快捷键：源码只判断 ctrlKey；模拟 Meta+N 没有新建，Control+N 可以新建 | 跨平台构建成功不能保证符合平台操作习惯 | Windows/Linux 使用 Ctrl，macOS 使用 Cmd；提示文字同步。保留纯文本输入的原生选中、撤销和粘贴行为。macOS 原生键盘仍需实机验收 |
| P1 | 多种菜单实现不同：复制菜单处理 Escape/箭头，但 Tab 留在菜单内；笔记更多菜单缺少统一焦点管理。实测多选中打开笔记菜单，Escape 同时退出多选 | 键盘用户容易迷失；关闭菜单顺带丢失选择 | 菜单统一处理打开、箭头、Tab 离开、Escape 仅关闭最上层并返回触发按钮。对话框、选择器、图片预览各自拥有键盘事件，不能一起清空全局状态 |
| P2 | 复制下拉目标实际为 20×28px | 两个相邻小按钮不易准确点击 | 扩到至少 28px 宽，桌面目标优先 32px。WCAG 存在间距例外，这里是易用性建议，不是完整合规判定 |
| P2 | 原生项目/筛选在宽窗内显示，窄窗变为辅助窗口；设置、帮助、更新等也打开独立窗口。App.svelte:188–203 | 相同操作因窗口大小改变承载位置，产生窗口寻找和焦点切换成本 | 默认稳定的主窗侧栏或覆盖面板；窄窗收起导航，不自动拆成新窗口。只有编辑笔记、图片大预览支持显式分离 |
| P2 | 编辑区长期展示所属项目、类型、标签；列表保留 Note 标签、工作笔记文案、工程类型 | 随手记需要扫描与当前目的无关的控件 | 新笔记默认进入收件箱；归类、标签和工程类型进入“整理/更多”。主列表不重复显示每条普通笔记的“笔记”标签 |
| P2 | 模板设置要求直接编写变量；没有真实样例的效果预览，没有模板删除和恢复预置入口 | 用户要理解语法才能配置，错误发现较晚 | 变量插入按钮、实际图文样例的即时预览；预置模板可恢复，自定义模板可重命名/删除。正文与图像是否含编号分别明确展示 |
| P2 | 通用成功反馈占据布局 5 秒；复制提示包含批次、配套提示词等术语 | 操作已完成后，反馈继续挤占空间，增加理解负担 | 成功在触发位置显示短暂“已复制”；非阻断消息不推挤正文。错误常驻且有具体恢复动作。批次仅放完整导出详情 |

P0 表示核心记录或数据忠实性；P1 表示高频流程与恢复能力；P2 表示发现成本和细节。该排序是设计优先级，不代表已经发生数据丢失。

## 建议的信息架构

宽窗采用“导航 / 笔记列表 / 当前内容”；小窗保留相同的笔记与任务概念，导航可以收起，笔记在当前窗内打开。快速记录入口始终可达，查找不用先选择工程类型。

- 主导航：收件箱、笔记本、任务；回收站放低频位置。
- 内容区：写作、图片、保存反馈；复制和更多固定在内容区顶部。
- 任务区：等待领取、处理中、已完成；任务详情含材料、说明、执行者、活动与结果。
- 设置：外观与窗口、导出模板、Agent 连接、数据与备份、更新通道。帮助可发现，更新当前版本和进度可见。
- 小窗标题栏：保留项目/笔记本切换、搜索和更多；帮助、更新、置顶、悬浮收起等移至更多。发现更新时可提供轻量标记。

不用为了普通记录与 Agent 协作增加全局“工程模式/笔记模式”切换。任务本身有状态，普通笔记的类型无需决定整个应用怎么工作。

## 五条目标流程

### 1. 随手记

新建 → 光标直接进入正文 → 输入或粘贴图片 → 反馈保存状态 → 切换下一条。

连续编辑不自动关闭窗；图片在光标处出现。失败保留输入，并具体提示哪条笔记没有持久化。空白新笔记离开时自动清理。当前 MCP 不暴露私有草稿的边界必须保持，任何自动保存正式笔记的改造都需要明确读取范围。

### 2. 复制与导出

选中内容 → 复制 / 导出面板 → 看见范围、顺序、格式 → 执行动作。

默认复制忠实的原文；有图片时可以选择图文。面板明确“仅正文”“图文”“全部图片”，模板只在主动选择后影响输出。预览同时显示文字和图片，不只显示一段 prompt。单条和批量复用同一面板，不再维护多份含义近似的入口。

图文剪贴板能力受目标软件限制。成功提示应该写明已经准备了几条正文与几张图片；目标仅接受文本时，提供完整包或 MCP 的替代路径。不要把操作系统写入剪贴板成功当成目标应用接收全部图片成功。

### 3. 批量整理

进入多选 → 当前视图选择 → 显示数量和范围 → 复制 / 更多 → 执行并反馈。

支持 Shift 范围选择、平台多选修饰键；Escape 优先关闭菜单，下一次才退出选择。删除可以撤销。移动后退出多选并提供“查看目标笔记本”，复制后保留选中，便于下一次输出。

### 4. 交给 Agent

选中材料 → 发布任务 → 预览材料和说明 → 等待领取 → 查看进展 → 查看结果。

材料快照与后续笔记修改分别展示。发布成功自动定位到任务，显示“等待领取”；Agent 未配置时提供连接入口。领取、释放、租期过期、撤回、完成分别有清晰状态文案。权限控制与撤回仍应按后端真实状态执行；不能用视觉上的撤销按钮冒充恢复了已失效的领取凭证。

### 5. 更新与恢复

打开更新 → 看见版本与通道 → 检查并更新 → 下载 / 保存 / 安装 → 恢复工作。

保留“一次检查并更新”的主动作。长任务有阶段反馈、重试与关闭策略；下载与安装开始后不能丢失进度。MCP 阻塞时说明哪个会话需断开，有可重试动作。用户手动断开会话之后，保留本次版本信息，不要求重新找安装包。

关闭编辑、关闭主窗和退出应用使用不同结果：编辑保存后离开；主窗按用户设置收进托盘；退出结束进程。托盘行为首次使用时解释一次，不在每次关闭时确认。

## 保留、收起和删除

| 决策 | 功能 |
| --- | --- |
| 保留并提升发现性 | 快速记录、搜索、正文/图文复制、图片原件、草稿持久化、任务队列、结果回写、帮助、签名更新 |
| 收到次级入口 | 工程类型、标签、状态筛选、图片编号、模板变量、窗口置顶、自动收起、MCP JSON、备份路径 |
| 合并入口 | 复制原文/正文统一命名；单条与批量使用同一交付流程；项目与筛选统一导航；任务结果从设置迁移到任务详情 |
| 默认流程取消 | 自动开关编辑窗口、自动拆辅助窗口、保存成功大提示、普通笔记强制状态、让用户管理交付批次 |
| 有替代能力后删除 | 不可撤销删除确认（先有回收站）；重复的“已打开笔记”管理（先能稳定切换）；Draft 工程上下文类型（先迁移到任务材料，保留旧内容） |

## 动效与输入约定

- 复制目标在悬停前后保持位置和宽度；悬停只改变背景，提示不能挡正文。
- 操作引起的面板出现可轻微淡入；保存、后台刷新和已复制提示不推动列表。
- 不能为了消除动效把目标瞬间搬到另一个位置；保持位置本身优先。
- 暂定微反馈 80–120ms、面板 120–160ms；这是待验证的产品参数，不是统一标准。
- 减少动态效果时取消非必要位移与缩放；仍立即呈现状态。
- 焦点返回触发控件；错误和成功通过适当的状态提示呈现，不自动抢焦点。
- 不全局拦截输入框的 Ctrl/Cmd+A、撤销、文本复制；中文输入组合期间不触发命令。

## 改造顺序与验收

1. 修正重试绑定、排序名称/行为、平台快捷键与菜单事件；这些不依赖编辑器架构重构。
2. 批量栏收敛、统一复制面板、任务视图从连接设置分离。
3. 明确保存语义后改主窗内编辑；实现有序图文块，完成旧数据、原图、模板和 MCP 的兼容。
4. 引入回收站与撤销，统一窗口和面板承载方式，再处理高级模板和动效。

下一轮验收任务：连续记三条内容；粘贴两图并在中间补文字；批量交付五条图文；复制失败后重试；筛选中改变选择范围；误删后恢复；发布后查看领取与结果；更新后恢复写作。

记录完成率、误操作、额外确认次数、寻找入口次数及用户能否正确解释保存和 Agent 状态。候选目标：随手记无需分类；成功关闭无确认；小窗批量栏不超过 56px；复制格式与顺序在所有入口一致；任何失败不会使输入消失。尚无用户样本与基线，暂不声称耗时或完成率已改善。

## 参考及采用范围

- [Apple Quick Note](https://support.apple.com/en-ae/guide/notes/apdf028f7034/mac)：快速唤起、继续上一条或新建。借鉴捕捉思路，不复制整个操作系统级入口。
- [Obsidian 附件](https://obsidian.md/help/attachments)、[模板](https://obsidian.md/help/plugins/templates)：附件属于内容，模板显式插入；不据此引入插件市场或知识图谱。
- [Bear 导出](https://bear.app/faq/export-your-notes/)、[复制格式](https://bear.app/faq/copy-portions-of-notes-as-html-rtf-txt-or-markdown/)：单条/多条导出与输出选项；本项目采用统一范围和格式面板。
- [Linear Agent](https://linear.app/docs/agents-in-linear)、[搜索](https://linear.app/docs/search)：连接配置与日常工作区分离、人工责任与 Agent 委派区分、搜索/命令可快速到达。DevPad 当前是本地任务拉取，不具备 Linear 的 Agent 自动调度能力。
- [NN/g 渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)、[识别与回忆](https://www.nngroup.com/articles/recognition-and-recall/)：高频动作直接呈现，低频选项清楚命名后展开。
- [NN/g 动效](https://www.nngroup.com/articles/animation-usability/)：动效要服务状态理解并考虑重复频率；不把吸引注意力作为每次操作的目标。
- [W3C 菜单按钮](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/)、[菜单键盘行为](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：用于校验菜单焦点、关闭、方向键与点击尺寸；本文没有进行完整无障碍认证。
