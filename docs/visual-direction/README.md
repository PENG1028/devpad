# DevPad 美术方向 · 01

本轮仅交付视觉概念与规范，不修改应用代码。评估依据为 docs/preview.png、当前样式及产品说明；不是运行中应用的逐屏验收。示意图中的记录为演示内容。

## 判断

现有三栏模型值得保留：项目与分类 → 记录 → 输出。主要问题是标题区占高、辅助文字偏小偏淡、编辑器与列表层级接近、附件缩略图抢眼、选择工具栏过长、右栏文本墙缺乏阅读结构。现代感应来自一致的排版、密度、状态和表面层级。

## 推荐方向

“精密而安静的开发工作台”：石墨灰导航、暖白内容、鸢尾紫动作。默认两栏专注记录，输出按需打开。保留本地工具定位；不增加聊天、云同步、账号或仪表盘。深色侧栏与浅色正文属于同一套混合主题，本轮不额外生成整套深色主题。

| 部位 | 视觉设计 |
| --- | --- |
| 品牌与侧栏 | 保留 dp + DevPad；小尺寸标记；项目选中用较亮底色；分类使用同系列线性图标或小圆点，数量右对齐；底部仅保留本地保存状态。 |
| 标题区 | 顶栏约 52px；项目名 24px/600；缩短宣传式说明；正文边距 24–32px。 |
| 快速记录 | 12px 圆角白色编辑区；类型选中使用淡紫背景；输入聚焦出现细紫描边；附件、快捷键和保存排列于底部。空内容保存按钮为明确禁用态。 |
| 搜索筛选 | 搜索框占主要宽度，状态和标签为紧凑次级控件；统一 32–36px 高度。 |
| 记录列表 | 正文 14–15px，行高约 1.65；日期 12px；用细分隔线保持连续阅读；选中采用淡紫底、2px 左线和勾选框。 |
| 附件 | 相同尺寸、8px 圆角、细边框；列表约 120×76px 缩略图，点击原图；避免大面积附件淹没正文。 |
| 多选工具栏 | 预留底部空间，避免遮挡记录；显示已选数量、完成、更多和 Copy for Agent；忽略、重新打开、删除收纳至更多，删除用语义红。 |
| 输出抽屉 | 宽约 360–400px；文档式预览划分标题、指令、引用和附件。复制文字为主按钮，复制图片和导出为次级动作；实际输出应保持原有顺序与内容完整。 |
| Draft 引用 | 延续相同编辑区；引用做成带序号的紧凑行，保留上移、下移和移除；不额外设计一种卡片系统。 |
| 弹窗和空状态 | 白色表面、12px 圆角、轻阴影；空状态使用一个线性图标、一句说明、一个动作。错误紧邻相关操作，明确说明并保留输入。 |

## 现成案例与借鉴范围

- [Linear：2026 界面更新](https://linear.app/now/behind-the-latest-design-refresh) —— 官方说明强调内容优先、降低导航视觉权重、柔化边框、统一顶栏。本方案借鉴其信息层级，不照搬项目管理功能。
- [Craft](https://www.craft.do/) —— 笔记与文档产品参考；本方案建议借鉴文档式阅读感、正文留白和图文组织，不引入其完整功能范围。
- [Raycast：Clipboard History](https://manual.raycast.com/clipboard-history) —— 文本与图片剪贴板工作流参考；本方案建议借鉴紧凑操作与快捷键提示，不增加全局启动器功能。

以上风格取舍为本项目的设计判断。UI/UX Pro Max 检索产出的落地页式单栏建议不适合当前工作台，已舍弃；保留其清晰文字、统一状态和克制动效原则。

## 生图与额度

已完成一次内置 ImageGen 调用，生成一张包含主界面、快速记录细节和交付预览细节的设计板，保存为 devpad-concept-01.png；没有追加变体。工具未暴露具体模型选择与金额预估，因此不声称已指定 Image 2 或具体费用。提示词保存在 image-prompt.txt。生图用于美术方向，不是可交互原型，文字和控件细节最终以此规范及实际产品行为为准。

目视检查：整体配色、三部分布局及中文主文案满足方向。图片中的演示计数未严格对应；左侧底部工具栏仍略微覆盖末条记录；按钮带有少许生成的渐变质感。正式设计应统一计数、为工具栏留足空间并改为纯色按钮。无需为这些局部细节追加生图消费。
